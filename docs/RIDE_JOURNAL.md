# Журнал заездов: общая лента итогов

План от 25.11.2026. Отдельный от [WORLD_TEMPLATES.md](WORLD_TEMPLATES.md), работа идёт в той ветке, где будет удобно. Проверки — по [CLAUDE.md](../CLAUDE.md): только изолированные сцены, без генерации мира.

## 1. Цель

Журнал — лента итогов заездов, **общая для всех миров и всех типов генерации** («Горная долина», «Речная экспедиция» и будущие). Каждая карточка: превью карты с проеханной линией, дата, мир и тип, ключевые цифры. Открытая карточка — крупное превью, профиль высоты и полная статистика. Ленту видно из меню и из дневника в игре.

## 2. Что есть сейчас (сверено по коду 25.11.2026)

| Где | Что делает | Почему этого мало |
|---|---|---|
| `scripts/game/ride_log.gd` (`RideLog`) | Заезд — игровая сессия от входа в мир до выхода. Хранит трек (отрезки `MapJournal`), велосипед/пешком, время, высшую точку, снимки, задания, места. До 40 записей. | Лежит **внутри сохранения мира** (`rides` в `SaveGame`). Другой мир или тип — другая история. Удалил сохранение — пропали заезды. |
| `scripts/ui/journal_panel.gd`, вкладка «Поездки» | Список «дата · расстояние · время», у выбранного трек на большой карте мира. | Работает только в игре и только для открытого мира: трек рисуется поверх карты этого мира. Карточек и превью нет, список читается как лог. |
| `scripts/game/map_journal.gd` (`MapJournal`) | Трек точками через 3,5 м, рвётся на переносах (> 30 м за такт). Кольцо из 256 отрезков по 128 точек. | Только X/Z, без высоты и скорости. Длинная сессия теряет начало трека. |
| `BikeRide` | `air_time`, `landing_info`, `crashed`. | В итоги заезда не попадают. |

**Вывод.** Данных для заезда почти достаточно, гипотеза «можно сделать легко» в целом верна. Узкие места не в UI, а в трёх вещах:
1. Хранилище должно жить **вне мира**, иначе ленты «на все типы» не будет.
2. Трек нельзя показать без карты мира, а грузить мир ради ленты нельзя (генерация занимает десятки секунд). Значит, **превью рисуется один раз, когда мир ещё открыт**, и хранится картинкой.
3. Высоты и скорости сейчас не пишутся. Сырые значения физики шумят: подвеска даёт «набор высоты» на ровном месте, рывки и сброс после падения дают ложную максимальную скорость. Нужны честные определения (раздел 5).

## 3. Что такое заезд

Оставляем нынешнее определение: одна сессия от входа в мир до выхода. Это просто и игроку понятно.

- `id` заезда = `<template_id>:<seed>:<start_unix>`. Запись в ленту — **upsert по id**: автосохранение и выход обновляют одну и ту же карточку, дублей не бывает, а при падении игры остаётся последняя версия.
- В ленту попадает заезд не короче 1 минуты или 200 м пути. Нынешние пороги 5 с / 5 м пропускают «зашёл и вышел».
- Пешие отрезки считаются, но главная цифра карточки — велосипед.
- Режимы разработки (`--quick-trails`, стенды, `short_dev`) в ленту не пишут.

## 4. Хранилище — `RideFeed`

Новый `scripts/game/ride_feed.gd`, без узлов сцены.

- Папка `user://ride_journal/`, **общая для всех типов** (это осознанное исключение из правила раздельных папок в разделе 7 WORLD_TEMPLATES: лента ничего не меняет в мирах). Файл `feed.json` и превью `thumbs/<hash id>.png`.
- Запись атомарная: `feed.json.tmp`, затем переименование. Битый файл — лента начинается заново, старый файл переименовывается в `.bad`, а не удаляется.
- Предел — 200 записей. Старые уходят вместе со своими превью.
- Поля записи:

| Поле | Что |
|---|---|
| `id`, `template_id`, `seed`, `world_title` | откуда заезд; название типа берётся из `WorldTemplate` при показе |
| `start`, `end` | unix-время; показ в местном времени (`RideLog.date_text`) |
| `time`, `moving_time` | всё время сессии и время в движении (скорость > 1,5 м/с) |
| `bike`, `foot` | м, из `MapJournal` |
| `climb`, `descent` | м, по определению из раздела 5 |
| `alt_max`, `alt_min` | м |
| `speed_max`, `speed_avg` | м/с; средняя = велосипед / время в движении на велосипеде |
| `jumps`, `air_max`, `falls` | число прыжков дольше 0,4 с, самый долгий полёт, падения |
| `photos`, `quests`, `places` | число снимков и заданий; названия мест строками (мира при показе нет) |
| `profile` | до 128 высот через равные доли пути — для графика |
| `thumb` | имя файла превью или пусто |
| `version` | формат записи |

Оценка размера: запись ~2 КБ, превью 320×200 PNG ~40–60 КБ, весь журнал до ~12 МБ.

## 5. Статистика: определения, чтобы цифры были честными

Сбор в `RideLog.tick` по точкам, которые уже пишет `MapJournal` (шаг 3,5 м), а не по каждому такту физики: это и дешевле, и убирает дрожь подвески.

- **Набор и сброс высоты** — с гистерезисом 2 м: высота засчитывается, только когда ушла от последней опорной точки больше чем на 2 м. Без этого кочки и подвеска дают сотни «метров набора» на ровной тропе.
- **Максимальная скорость** — по окну 1 с (путь за секунду / 1 с), а не по мгновенной скорости физики. Окно сбрасывается на разрывах трека (`MAX_STEP`, перенос, подъём после падения), иначе телепорт даёт 100 км/ч.
- **Прыжок** — `landing_info.air ≥ 0,4 с`. Короткие отрывы на кочках не считаются.
- **Падение** — фронт `BikeRide.crashed`.
- **Профиль** — высоты земли под игроком в точках трека, затем равномерная выборка по пройденному пути до 128 значений.
- **Ограничение трека.** Кольцо `MapJournal` (256 × 128 точек) может съесть начало очень длинной сессии. Для ленты это допустимо: цифры считаются нарастающим итогом и не зависят от кольца, обрезается только линия на превью. Это записано как известное ограничение, а не исправляется.

## 6. Превью трека

`scripts/ui/ride_thumb.gd` — чистая функция `Image`, без вьюпорта и без GPU:
1. Берём `map_image` мира (уже есть в игре), вырезаем рамку трека с полями 12% (как `world_map_view._frame_ride`), сохраняем пропорции. Для узких длинных миров Типа 2 добавляем поля по короткой стороне.
2. Масштабируем до 320×200 и рисуем линию трека в 2 px: велосипед — светлый цвет, пешком — пунктир. Отмечаем старт и финиш.
3. PNG пишется в `thumbs/` при upsert, но не чаще раза в 60 с и обязательно на выходе. Рисование занимает единицы миллисекунд (до 6000 точек), поэтому отдельный поток не нужен. Если замер покажет больше 4 мс, перенесём в `WorkerThreadPool`.

## 7. Интерфейс

- **Вкладка «Поездки» в дневнике** становится лентой карточек: превью, дата, мир · тип, `велосипед · время · набор`. Фильтр «Этот мир / Все». Заезд этого мира по нажатию, как и сейчас, показывает трек на большой карте. Заезд другого мира открывает крупное превью и профиль.
- **Главное меню** — кнопка «Журнал заездов». Открывает ту же ленту без карты мира (только превью и профиль).
- **Карточка подробно**: крупное превью, график профиля высоты (`Line2D` или `draw_polyline` по `profile`), сетка цифр из раздела 4, места и снимки (снимки — если файл ещё есть). Есть кнопка «Удалить запись».
- Блок «Итого за путешествие» остаётся во вкладке как есть: это итог по миру.
- Одни компоненты для меню и для игры: `ride_feed_view.gd` (лента) и `ride_card.gd` (карточка). `journal_panel.gd` их вставляет, а не дублирует.

## 8. Переход со старых записей

При загрузке сохранения его старые `rides` переносятся в ленту upsert по id (`id` собирается из `start`). Превью для них рисуется тут же, ведь мир уже открыт. Новых полей (набор, скорость) у старых записей нет: в карточке они показываются прочерком. Поле `rides` в сохранении остаётся для совместимости, но новые заезды туда больше не пишутся.

## 10. Что сознательно не делаем

- Не делим сессию на несколько заездов по паузам и не ищем «сегменты» трассы. Это можно добавить позже, поверх тех же записей.
- Не храним полный трек с высотами всех точек: для ленты хватает превью и профиля из 128 точек.
- Не делаем облачную синхронизацию и экспорт GPX.
- Не трогаем графику мира.

## 11. Открытые вопросы к пользователю

- Считать ли пешие сессии без велосипеда отдельными записями или скрывать их? Предлагаю скрывать, если велосипедом проехано меньше 200 м.
- Нужна ли кнопка «Журнал заездов» в главном меню или достаточно вкладки в дневнике? Предлагаю оба места: ведь смысл ленты — видеть заезды всех миров, не открывая мир.
