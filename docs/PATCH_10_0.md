# 10.0 — список миров в меню и кэш готовых миров

Контроль: Север-1234@512 (план 768 × 768), Ryzen 7 2700, GTX 1650 SUPER, `check.gd --cache`. Генерация не менялась.

## Меню

Под полем зерна три вкладки:

- **Недавние** — три последних запущенных мира, новый сверху;
- **Избранное** — миры со звёздочкой (до 12), остаются, пока звёздочку не снять;
- **От автора** — рекомендованные миры. Список ведёт автор в `scripts/data/recommended_seeds.gd`: одна строка
  `{seed = "Зерно", note = "Чем мир хорош"},` на мир, игроки его только видят. Сейчас там четыре контрольных мира
  из `tools/control/seeds.json`, у «Ущелья» подпись «Много мостов через ущелья».

Щелчок по миру ставит его зерно в поле (и фокус на «Начать игру»), звёздочка в строке добавляет мир в избранное или
убирает его оттуда. Пометка «готов» — мир лежит в кэше и загрузится быстро. Если недавних нет, открывается вкладка
«От автора». Списки хранятся в `user://settings.cfg` (`[world] recent`, `favorites`), битые записи пропускаются.

## Кэш миров

`scripts/world/world_cache.gd` (`WorldCache`), файлы в `user://world_cache/*.wgc`.

**Что хранится.** Только результат генерации: поля `WorldData` после всех этапов (сжатые zstd). Генерация — 46–48 с
из ~67 с загрузки мира 768; остальное (заливка карты, рельеф, меш, вода, полотно дорог) считается из готовых данных,
и класть это в файл значило бы увеличить его в несколько раз ради ~8 с. Шумы пересоздаются из сида, поэтому мир из
кэша тот же: в проверке совпали сводка мира, высоты рельефа после дорог, карта и число объектов.

**Какие миры.** Последние три и избранные. Остальные файлы удаляются при запуске игры, при старте мира и при снятии
звёздочки. Примерно 20 МБ на мир, то есть до ~300 МБ при полном избранном.

**Защиты.**

- В ключе файла версия игры (`application/config/version`), формат кэша, зерно, размер плана и окна: после патча
  старый файл не подходит и удаляется при первом запуске. Генерацию надо менять только вместе с номером версии
  (так и делается в каждом патче); если поменять генерацию, не меняя версию, кэш отдаст старый мир.
- Заголовок с проверкой размеров и SHA-256 сжатых данных; после распаковки — проверка, что все поля на месте, их
  типов и длин массивов (по клеткам, по объектам, чанки) и что номер сида совпадает с зерном. Битый или чужой файл
  удаляется, мир генерируется заново.
- Запись в фоне (`WorkerThreadPool`) через временный `.tmp` и переименование. Снимок данных берётся сразу после
  генерации, до того как мир кто-то тронет. При выходе из игры запись дожидается.
- Кэш включает только сама игра (главная сцена). Инструменты проверки ставят меню не главной сценой и генерируют
  честно; `check.gd --cache` включает его в отдельной папке прогона и удаляет файл в конце.

## Результат

| | Загрузка, с |
|---|---:|
| С генерацией (первый запуск мира) | 71,6 |
| Из кэша | 35,3 |

Файл 20,2 МБ, чтение и проверка 0,33 с. Остальная загрузка из кэша: заливка ‖ рельеф (~9 с, в двух потоках),
полотно дорог и сооружения 8,2 с, правка меша 2,6 с, текстура и карта 2,2 с, запуск сцены ~4 с. Следующий запас —
класть в кэш ещё базовый рельеф и заливку (−8 с при файле примерно вдвое больше); полотно дорог (8 с) из кэша не
восстановить без сохранения внутренностей `Heightfield`.

Попутно: состав лесной подстилки (`forest_surface`) считается, пока идёт заливка, а не после неё.

## Проверка

`check.gd --cache` (новый ключ): обычная единая проверка, затем возврат в меню и загрузка того же мира из кэша
со сравнением. Итог в `runs/10.0/cache.json`.

- Проверено: мир из кэша совпадает (сводка, высоты, карта, объекты), время загрузки, размер файла; виды и FPS
  Север-1234@512 (осмотр 187, дорога 188 FPS). Меню — один снимок вкладок.
- Не проверено: сравнения с 9.9 нет — прогон 9.9 снимал мир с окном 768, а не 512 (генерация не менялась).
  Во время проверки был открыт ещё один Godot (вероятно, редактор), время загрузки могло сдвинуться.
  Битый файл кэша, обрыв записи и смена версии вручную не проверялись — только кодом проверок при чтении.
  `lifecycle_test` не запускался: освобождение мира не менялось.
