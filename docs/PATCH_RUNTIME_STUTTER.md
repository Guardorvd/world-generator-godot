# 27 октября 2026: остановки при движении с навигацией

Проверено в настоящем окне: Trail Lab открывается кнопкой главного меню,
Esc возвращает в меню; обычный мир «Гроза-4711» загружается. Дополнительно
`trail_lab_menu_test.gd` проверяет повторный вход и освобождение сцены с ragdoll.

## Причина и история

В патче `6890988` от 26 октября появился поиск проходов через реальный рельеф,
воду, сооружения и препятствия. Построение дорожного графа и поиск пути
выполнялись синхронно в `NavigationLine.set_goal/update_line`. При отказе
проверки ближайшей линии заново собиралась вся сеть; пустой путь также
запускал периодическую повторную сборку. Это создавало многосекундные кадры.
Проверка прибытия к свободной метке могла дополнительно проверять весь
отрезок до далёкой цели каждый такт физики, до проверки радиуса прибытия HUD.

Изменения от 27 октября (`42b97c6`: растительность/предиктивный стриминг,
`50faff9`: камни, `d1f227c`: C# генерация, `bd5fe67`: Trail Lab,
`7a0c943`: тормозной индикатор) также просмотрены. В описаниях графических
патчей явно указано отсутствие замера FPS полного мира. Они не доказывают
сохранение прежней производительности. В первом замере без навигации
зафиксированы 78 FPS на движении и максимальный кадр 29 мс; это отдельный
контрольный прогон, не историческая база «200 FPS».

## Изменения

- Игра использует одну фоновую задачу навигации. Её вход — частный снимок
  доступной территории, рельефа, воды, построек, сооружений и препятствий.
  Опубликованные неизменяемые поля разделяются; изменяемые таблицы/кэши
  копируются. Главный поток не ждёт незавершённую задачу при отрисовке.
- Новая цель/ревизия отменяет старый запрос. Устаревший результат не применяется.
  Выход из сцены отменяет и присоединяет задачу; узлы GPU меняются только
  главным потоком. После принятия пути локальные проверки используют живой мир.
- Неизменённый граф переиспользуется. При изменении препятствия полный
  повторный расчёт тоже идёт в фоне. Синхронный API сохранён для инструментов.
- Кандидаты построек индексируются по локальным участкам 64 м. Для каждой
  точки остаются исходные точные проверки повёрнутых домов, стен, воды и объектов;
  перебор поселений всего мира исключён.
- Проверка линии ограничена видимыми 70 м, включая длинные конечные отрезки.
- Проверка прибытия к метке сначала отсекает расстояния больше 3 м, затем
  проверяет уровень, воду и свободный последний подход.

## Замер

`tools/runtime_stutter_probe.gd` запускает Vulkan, 1280×720, без VSync,
с высокой дальностью растительности (2), в мире «Гроза-4711».
Сначала осмотр, затем повторяемый пролёт 12 м/с по самой длинной дороге
с активной меткой. Это замер отрисовки, навигации и подгрузки;
физика игрока при пролёте приостановлена. Прогресс и настройки не записываются.
В JSON сохраняются все кадры, p99, максимумы, GPU/CPU и стоимость подсистем.

Для сравнения исходная `navigation_line.gd` из HEAD сохранена в игнорируемой
папке прогона; инструмент принимает её через `--reference-line`. Оба варианта
используют одинаковый маршрут, высоту ног и параметры графики.

```text
godot --path . --script tools/runtime_stutter_probe.gd -- --mode nav --out tools/control/runs/stutter.json
# Без активной навигации: --mode normal
# Контроль с зафиксированным окружением: --mode frozen
# Исходный файл линии: --reference-line res://tools/control/runs/navigation_legacy.gd
```

Итог последнего проезда (GTX 1650 SUPER, один прогон каждого варианта):

| Навигация | Средний FPS | p99 кадра | Максимальный кадр |
| --- | ---: | ---: | ---: |
| Исходная, корректная высота ног | 47.3 | 40.0 мс | 2197.6 мс |
| Исправленная, локальный индекс | 67.2 | 30.3 мс | 43.5 мс |

Запрос цели: 1980 мс → 4.7 мс в главном потоке. Сам поиск продолжает
выполняться в фоне. Более ранний диагностический прогон с высотой камеры
вместо высоты ног усиливал пересчёты до 5881 мс; итоговая таблица использует
контрольный прогон с корректной высотой ног в обоих вариантах.

Артефакты сравнения: `stutter_legacy_feet.json`, `stutter_fixed_v2.json`,
окончательные прогоны `stutter_final.json` и `stutter_indexed.json` в `tools/control/runs`.
Во втором прогоне устранены многосекундные блокировки; остаточные пики
отрисовки линии/подгрузки и общий FPS требуют отдельной оценки. Возврат
к 200 FPS для всех миров этим исправлением не заявляется.

Проверки: `navigation_async_test.gd` (снимок, публикация, отмена, смена
ревизии, освобождение, дальняя метка, горизонт линии),
`bike_recovery_test.gd` (51 проверка навигации/размещения),
`trail_lab_menu_test.gd` (настоящее меню и жизненный цикл Trail Lab).
