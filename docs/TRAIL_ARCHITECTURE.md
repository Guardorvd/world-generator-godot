# Велосипедные трассы и Trail Lab

Основа подготовлена в ветке `visuals` поверх 14.10. Это отдельный слой авторских трасс,
который можно подключить к подготовке мира; автоматическое размещение в основных мирах
и изменение существующих сохранений в эту работу не входят.

## Что уже есть в проекте и что используется повторно

| Система | Ответственность для трасс |
| --- | --- |
| `WorldData` / `CivilInfrastructureData.trails` | Единственные игровые линии путей, маски проходимости, покрытия |
| `StageTrails` | Процедурные дороги, поиск пути, мосты и туннели; новый генератор не создаётся |
| `RoadSurface` | Идентификаторы и свойства покрытий: сцепление, скорость, шероховатость, цвет |
| `RoadBed` / `RoadRefinement` | Подготовка полотна и метровая сетка, защита воды и сооружений |
| `Heightfield` | Единая опора для ходьбы, велосипеда, воды и физики падения |
| `TerrainBuilder` / `RoadBump` | Настоящий меш, материал, общие визуальные и физические неровности |
| `BikeRide` / `BikeBrakes` | Баланс, торможение, снос, полёт, приземление, подвеска |
| `BikeController` / `Stamina` | Игровое усилие, посадка/сход, переходы падения и восстановления |
| `BikeView` / `BikeCrash` | Модель с седоком и штатная физика падения |
| `ServiceScope` | Собственные сервисы лаборатории без сброса глобального игрового контекста |

`RideSurface.sample()` выделен из прежнего блока `BikeRide.step()` без изменения формул.
Его используют и велосипед, и показания лаборатории: surface, вес контакта и поперечная
координата берутся из `RoadRefinement.sample`, с прежним fallback на `tile_info`.
Сцепление с учётом скорости и тормозов по-прежнему вычисляет сам велосипед.

## Выбранная архитектура

Используются обычные Godot `Resource` (`.tres`) и существующий heightfield. Дополнительный
физический движок, отдельный navmesh и независимый меш трамплинов здесь не нужны.
В основной игре уже работает собственная кинематика велосипеда; замена её на
`VehicleBody3D`/колёсные RayCast изменила бы поведение всей игры.

`TrailDefinition` описывает стабильный id, название, тип пути, осевую ломаную, ширину,
необязательное покрытие и массив `TrailElement`. Координаты задаются в **мировых метрах**:
`Vector2.y` означает Z. `width` — полная ширина. Высота оси берётся из настоящего рельефа,
поэтому описание не содержит второй версии профиля земли.

`TrailElement` содержит профиль земляного элемента, расстояние от начала трассы
(`station`), длину, высоту и сторону подъёма поворота (`bank`). Сейчас есть роллер,
стол и профилированный поворот. Следующий тип можно добавить через переопределение
`displacement()` в наследнике, сохранив прежний цикл опоры и движения.

`TrailBuilder.append_routes()` сначала проверяет весь набор. Ошибочные id, геометрия,
выход за подготовленную область и некорректные элементы отклоняются до записи в мир.
После проверки трассы становятся обычными `w.trails` с дополнительными `trail_id`
и `surface_override`; `TrailDefinition.path_record()` переводит точки и ширину
в существующие клетки. Маску пишет `Grid.stamp_path`, покрытия выбирает общий
`RoadSurface.assign_route()`. Уже назначенные покрытия старых путей сохраняются;
общая карта покрытий перестраивается в штатном детерминированном порядке.
`RoadSurface.run()` учитывает явное покрытие и при последующем штатном расчёте:
интеграция не зависит от ручного повторного назначения покрытий после генерации.

`TrailBuilder.bake_elements()` вызывается **один раз на свежем** законченном рельефе.
Он меняет только высоты существующих метровых патчей `RoadRefinement`, до построения
меша. Соседние патчи получают одинаковое смещение общей вершины. Поэтому
`ground_at`, `surface_at`, `TerrainBuilder` и `BikeCrash` видят один профиль.
Новая физика прыжка не добавляется: с роллера велосипед отрывается штатным способом.
Метод возвращает список ошибок, как `append_routes`. Повторное запекание, изменение
геометрии после подготовки полотна и отсутствующая трасса отклоняются и в release.
Высоты сначала рассчитываются во временных массивах. Если расширение вернуло NaN/INF,
исходные патчи и состояние запекания остаются прежними. В `build_timings` хранится
только длительность `trail_elements_ms`, состояние — в `trail_elements_baked`.

Защита земляных работ:

- плавное затухание к боковой границе трассы и концам элемента;
- отсутствие изменений в водных клетках, затухание к берегам по `dist_water`;
- сохранение подходов к мостам и туннелям по штатным `PIN`/`PIN_FADE`;
- сохранение полного полотна пересекающих дорог, даже если ближайшая линия — тропа;
- ограничение суммарного смещения двумя метрами;
- минимальная длина элемента четыре шага уточнённой сетки.

Тип `mountain` выбран для технических участков лаборатории: существующее сглаживание
обычной дороги/тропы не должно уничтожать задуманный профиль. `trail` подходит для
обычного singletrack, `road` — для соединений с сетью, без земляных элементов.

## Trail Lab

Нажать **Trail Lab** в нижней строке стартового меню. Для запуска из редактора можно
также открыть `scenes/trail_lab.tscn` и нажать F6 или выполнить:

```powershell
godot --path . res://scenes/trail_lab.tscn
```

Четыре площадки: грунтовые роллеры, каменный стол, лесной поворот, песчаное торможение.
Параметры лежат в `resources/trails/lab/*.tres`; редактируются инспектором Godot.
Собственные ресурсы можно назначить массиву `routes` корня сцены. Пустой массив
подключает четыре стандартных ресурса. Числовые клавиши выбирают трассу, R возвращает
к её началу, V включает общий обзор, E переключает посадку/сход, Esc возвращает в
стартовое меню. При отдельном запуске сцены Esc закрывает лабораторию.
W/S, A/D, Space и Shift используют общие игровые действия.
F3 раскрывает и скрывает подробную телеметрию и подсказки управления;
по умолчанию остаются только основные показатели заезда. Кнопки HUD также
открывают настройки, переключают камеру и показывают подробные данные.

F2 открывает панель выбора трассы/элемента и настройки ширины, покрытия, профиля,
положения, длины, высоты и стороны поворота. «Применить и проверить» готовит новый
рельеф и меш, затем заменяет текущую площадку. Ошибка оставляет прежнюю сцену проходимой
и показывает причину. Правки действуют в текущем запуске и не меняют исходные общие
ресурсы. Для постоянного сохранения параметров используется инспектор `.tres`.
F5 перечитывает ресурсы из файлов без перезапуска. G запускает заезд за 12 метров
до начала выбранного элемента с заданной в панели скоростью. Направление старта
вычисляется по оси трассы, поэтому пользовательская трасса может смотреть в любую сторону.
После построения включается обзор сверху; кнопка «Камера» в панели или клавиша V
переключает его на обычный вид за велосипедистом и обратно. Заезд включает обычный вид.
Панель прокручивается по вертикали, её поля помещаются в окно 1280×720.
Настройки построения, покрытия, элемента и рельефа раскрываются отдельными группами.
Кнопки внизу панели остаются на месте при прокрутке: «Применить и заезд»
перестраивает трассу, а «Заезд без правок» использует текущую площадку.

`tools/trail_lab_fixture.gd` создаёт только маленькие исходные данные площадки 64×64
клетки с известным уклоном. Он не переопределяет `Heightfield`, `WorldData.tile_info`,
покрытия или велосипед. Дальше работает производственная цепочка сборки.
Камера и диагностические подписи принадлежат лаборатории. Игровые меню, задания,
сохранения, растительность и стриминг полной карты для неё не запускаются.

Падение использует настоящие `BikeController` и `BikeCrash`. Восстановление возвращает
пешехода; E позволяет поднять и оседлать велосипед через штатную проверку посадки.
Лаборатория не подменяет падение мгновенным телепортом. Пешая ветка вызывает
`Stamina.tick_foot`, сообщения отказа посадки видимы пользователю, однотактовые события
приземления и пробоя подвески очищаются после передачи в `BikeView`, как в `GameWorld`.

## Порядок последующей интеграции

1. Получить определения трасс на этапе подготовки civil-слоя, после `StageTrails`,
   до раскладки растительности и снимков масок. Вызвать `append_routes` на данных,
   которыми эксклюзивно владеет подготовка. При ошибке не публиковать результат.
2. Закончить штатные покрытия и `Heightfield.finish_paths()`. `RoadSurface.run`
   автоматически сохраняет явное покрытие из `surface_override`.
3. Сразу вызвать `bake_elements`, затем `TerrainBuilder.refine_arrays` и
   `PlanTerrain.partition`. В `WorldLoader` эта точка находится между `finish_paths`
   и уточнением/разбиением меша. Проверить возвращённые ошибки до публикации.
   Не менять патчи уже опубликованного потока.
4. Дать `RoadNavigation` обычные линии `w.trails` и готовый `Heightfield`.
   Новый граф маршрутизации не требуется. Направление гонки, контрольные точки и
   сложность относятся к будущему спортивному слою, а не к физике поверхности.
5. Для сохранения авторских данных хранить ресурсы/id и их ревизию. Одного
   `trail_id` в словаре пути недостаточно для восстановления земляных элементов:
   `WorldCache` пока не хранит `TrailDefinition`. До подключения в основную игру
   добавить версию/сериализацию определений и повторное запекание при чтении кэша.
6. Для соседних регионов использовать общий мировой адрес, один владелец id,
   коридор данных за границей и одинаковое запекание общих вершин. Текущий адаптер
   намеренно отклоняет след, выходящий из подготовленной области. Публикацию,
   выгрузку и повторную подготовку подключать через `RegionPreparation`/`RegionStream`.

До массового размещения нужно добавить пространственный индекс элементов по чанкам:
сейчас их проход линейный и рассчитан на небольшую площадку/подготовку отдельного
набора, а не тысячи трасс мира. Пересекающиеся земляные элементы суммируются с
ограничением высоты; автоматический анализ безопасного приземления пока отсутствует.
Самопересечения оси выбирают ближайший сегмент; развязки и навесные настилы требуют
отдельного контракта сооружений. Heightfield не представляет вертикальные стенки,
нависающие рампы и настоящий gap без земли. Их следует добавлять к существующей
системе сооружений и контактов, а не имитировать декоративной геометрией.

## Проверка

```powershell
dotnet build --no-restore
# После появления новых class_name — один импорт проекта.
godot --headless --editor --path . --import
godot --headless --path . --script res://tools/trail_lab_test.gd
# Вместо headless для трёх снимков:
godot --path . --script res://tools/trail_lab_test.gd -- --capture
# При изменении только панели — снимки и проверка размещения без повторения физики:
godot --path . --script res://tools/trail_lab_test.gd -- --ui-only
# Кнопка меню и повторный вход, без генерации фонового мира:
godot --path . --script res://tools/trail_lab_menu_test.gd -- --capture
```

На машинах без Vulkan/D3D12 можно передать
`--rendering-method gl_compatibility --rendering-driver opengl3_angle`.
Отчёт: `tools/control/runs/trail_lab/metrics.json`; снимки: `overview.png`, `rider.png`,
`editor.png`. `--ui-only` сохраняет эти снимки, но не перезаписывает отчёт физики.
Тест проверяет транзакционный отказ, общие покрытия, соответствие всех треугольников
меша опоре, реальные проезды/подвеску/отрыв/торможение, поворот рулём, 30/120 Гц,
защиту воды, сооружений и пересекающей дороги, повторяемость свежей сборки.
Дополнительно проверяются повторный штатный расчёт покрытий, отказ повторного/устаревшего
запекания, ошибочный профиль расширения, изменения через настоящую сцену и их откат,
перечитывание ресурсов, старт на восток, пешее восстановление выносливости и потребление
однотактовых событий. Падение с высоты на роллер проходит настоящие физические кадры:
потеря равновесия → ragdoll → восстановление → ходьба → сброс заезда.

Последняя проверка: 40 проверок данных/механик/сцены и отдельно 2 проверки размещения
панели при 1280×720; ошибок нет. Сборка .NET выполнена. Снимки просмотрены.

Полная генерация, стриминг и сохранение авторских элементов этой проверкой не покрываются.
Они нужны при подключении в основную игру; текущий результат — архитектура и лаборатория
для подготовки этого подключения, а не автоматическая расстановка трасс в готовых мирах.
