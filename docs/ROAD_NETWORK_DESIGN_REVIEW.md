## 1. Сначала структура сети, затем форма маршрута

### Что происходит сейчас

StageTrails._settlement_trails последовательно выбирает пару поселений и вызывает полный поиск. _add_trail уменьшает стоимость клеток и соседей; новые маршруты начинают тяготеть к уже готовым. Сооружения также меняют доступность и высоты. Получается полезное слияние дорог, но структура зависит от последовательности строительства.

RegionRoads выбирает пары по прямому расстоянию, а старую сеть представляет ближайшей клеткой. Для формы используются восьмисвязный поиск, проверки полосы, обработка мостов/туннелей и безопасное сглаживание. Последующее RoadBed/RoadRefinement меняет поверхность. Решения о связности, форме и возможности земляных работ оказываются разнесены по этапам.

Pathfinder.use_corridor сейчас означает проверку ширины каждого шага, а не ограничение поиска пространственным коридором. Существующий флаг сам по себе не сокращает поиск до полосы вдоль предварительного маршрута.

### Предлагаемые уровни

1. **Неизменяемая география.** Высоты, вода и её уровни, тип грунта, запреты изменения, существующие сооружения; мировые идентификаторы и локальные версии участков.
2. **Граф возможных проходов.** Кластеры и проходы между ними; специальные рёбра для переправ, перевалов, туннелей и входов в старую сеть. Обычная граница кластера — диапазон возможного пересечения, а не единственная точка посередине стороны. Внутри одного кластера могут быть раздельные компоненты суши.
3. **Каркас сети.** Какие центры соединяются, где общий ствол и где ответвления, какие переправы совместно используются. Сначала обязательная связность, затем полезные петли. Подключение к существующей дороге — к набору доступных мест, не только к ближайшему по прямой.
4. **Коридор маршрута.** Несколько географически разных предварительных вариантов; детальный поиск только в выбранных кластерах и их ограниченном соседстве. При неудаче расширить коридор или сменить проход; сохранять различие между «не найдено в этом коридоре», «кончился бюджет» и «невозможно».
5. **Форма и профиль.** Линия с плавными поворотами, согласованные уклоны, ширина, план выемок/подсыпки, подходы к мостам. Финальная проверка построенной полосы на той же поверхности, которую читают движение и коллизии.

Каркас не должен быть только деревом кратчайших расстояний между поселениями. Дерево на географических стоимостях подходит как начальное решение, но затем нужны общие стволы, явные примыкания и немного полезных петель. Минимизация стоимости новой построенной дороги и стоимости поездки — разные цели. Скидку за существующую дорогу лучше задавать классом ребра, а не повторным умножением стоимости клетки, зависящим от количества прошедших по ней маршрутов.

Граф спроса между поселениями и граф физических дорог хранить отдельно. Несколько связей спроса могут использовать один участок дороги. Это позволяет проектировать и строить этот участок один раз.

### Какие методы подходят

| Подход | Решение для проекта |
|---|---|
| HPA*: кластеры, граничные проходы, повторное использование локальных переходов | Основной ориентир. Начать с фиксированных мировых кластеров, учитывать географические узкие места; дорогие переходы уточнять по необходимости. Не рассчитывать заранее все пары всех входов. |
| Разделение топологии и изменяемых стоимостей, как в Customizable Route Planning | Использовать принцип: стабильный граф проходов, отдельный слой уже построенных дорог и локальное обновление затронутых переходов. Полный алгоритм для континентальных дорожных графов здесь избыточен. |
| Многоточечный Dijkstra от сети | Полезен для нескольких подключений к одной сети на одном снимке. Сначала использовать на маленьком графе проходов. Полный растровый поиск ради одного подключения может проиграть A*. |
| Theta*/поиск под произвольным углом | Возможное улучшение формы внутри коридора. Видимости оси недостаточно: нужна проверка ширины, воды, уклона и земляных работ. Длинные проверки отрезков могут съесть экономию. |
| Двунаправленный поиск | Локальная альтернатива для длинного участка. Не заменяет иерархию, не гарантирует ускорения и сам по себе не означает выполнение на двух потоках. |
| D* Lite/инкрементальный поиск | Рассмотреть для повторного исправления того же маршрута после локального изменения. Не основной инструмент для множества разных пар с разными целями. |
| Обычный Jump Point Search | Не прямая замена: исходный метод рассчитан на равностоимостную сетку, а здесь неоднородные стоимости, уклоны и сооружения. |

Основания: [HPA*](https://webdocs.cs.ualberta.ca/~mmueller/ps/2004/hpastar.pdf), [CRP](https://tpajor.com/assets/paper/dgpw-crp-11.pdf), [Theta*](https://idm-lab.org/bib/abstracts/Koen07f.html), [D* Lite](https://publications.ri.cmu.edu/d-lite), [JPS](https://pathfinding.ai/pdf/harabor-grastien-aaai11.pdf). Применимость и приоритеты в таблице — выводы для этого проекта, не результаты этих публикаций.

### Как действительно не обрабатывать весь мир

Недостаточно запретить выход за коридор, продолжая выделять, копировать и предвычислять поля размером со всю карту. Рабочие массивы A*, маски и данные полосы также должны быть локальными: компактные прямоугольники либо наборы тайлов, мировые адреса преобразуются на входе/выходе.

Ключ кэша перехода: вход/выход, ширина и класс дороги, разрешённые сооружения, политика земляных работ, версии затронутых географических тайлов и стоимости сети. Ошибка из-за исчерпания бюджета не является кэшируемым доказательством отсутствия пути. Географический кэш не сбрасывать целиком после добавления дороги; но изменение стоимости может сделать ранее отвергнутый вариант выгоднее.

Укрупнение должно сохранять узкие проходы. Средняя высота крупной клетки не доказывает её проходимость. Разреженный набор порталов приблизителен: при локальной неудаче допускается ограниченное добавление порталов. Ограничить память, время подготовки и число локальных альтернатив.

## 2. Параллельный расчёт дорог и частей одного маршрута

### Почему схема 40–20–40 не должна быть буквальной

Два поиска от концов без общего плана могут прийти к разным перевалам, противоположным берегам или несовместимым высотам. Средние 20% окажутся самым сложным участком. Даже совпадение позиции не гарантирует совпадения направления, высоты, уклона и ширины.

Суть идеи полезна: независимые подходы плюс зона согласования. Но делить нужно по географии и оценке сложности, а не по расстоянию. Переправа вместе с обоими подходами — одна задача. Развилка — один общий узел проектирования. Длинная открытая долина допускает несколько задач.

### Рекомендуемая схема: коридор, варианты стыков, независимые задачи

1. На верхнем графе выбрать общий коридор и несколько обязательных проходов. Это малая задача относительно растрового поиска.
2. Выделить участки с учётом ожидаемых раскрытий, ширины коридора и сложности рельефа. Короткую дорогу не делить. Границы ставить на относительно спокойных местах, вне мостов, развилок и крутых поворотов.
3. Для каждого стыка определить небольшой набор конкретных состояний: мировая позиция, высота полотна, направление касательной, продольный уклон, ширина, класс дороги и версия поверхности. Интервалы высот допустимы в предварительной оценке, но для окончательного соединения выбирается совместимое состояние.
4. Посчитать локальные варианты переходов между соседними наборами состояний независимо, на неизменяемом снимке. Не перечислять автоматически весь декартов продукт: начинать с небольшого числа перспективных вариантов, уточнять по запросу согласователя.
5. На маленьком слоистом графе выбрать совместимую цепочку переходов. Это динамическое программирование по состояниям стыков. Вариант, более дорогой внутри одного участка, может дать существенно лучший маршрут целиком.
6. Уточнить выбранные участки параллельно с перекрытием рабочих областей. Перекрытие обеспечивает контекст для формы, но само по себе не согласует высоту. У каждой итоговой вершины и зоны стыка должен быть единственный владелец.
7. Выполнить короткую общую проверку линии и профиля. При конфликте перепланировать локальный участок или стык; при несовместимости всего прохода поднять отказ на уровень коридора. Ограничить число согласований.

Полный минимум гарантируется лишь внутри выбранного дискретного графа состояний при корректно учтённых зависимостях, а не среди всех дорог мира. Для общего бюджета земляных работ хранить несколько недоминируемых вариантов «стоимость–объём» либо использовать штраф и отдельную итоговую проверку. Одна самая дешёвая локальная метка может потерять допустимое глобальное решение.

Начальная реализация проще: фиксированные согласованные состояния стыков, параллельное уточнение участков и один локальный ремонт. Наборы вариантов и динамическое программирование добавлять, если жёсткие стыки заметно ухудшают форму или приводят к отказам.

Высотный профиль после выбора оси можно согласовать отдельной небольшой одномерной задачей по всей дороге: границы выемки/подсыпки, максимальные уклоны и условия концов. Если профиль неосуществим, возвращать конкретную проблемную зону на локальный поиск оси. Не считать, что последующее сглаживание автоматически сделает любой маршрут допустимым.

Для двунаправленного поиска нельзя останавливаться на первом соприкосновении фронтов: нужна корректная граница стоимости незавершённых вариантов. «Середина» в исследованиях — середина стоимости решения, не геометрические 50%. Текущий H_COST=0.6 может превышать минимальную стоимость 0.3; существующая эвристика не даёт автоматически перенести гарантии оптимального двунаправленного алгоритма. См. [MM](https://ojs.aaai.org/index.php/AAAI/article/view/10436).

### Параллельно разные дороги

Существующие _connect_settlement/_structures/_add_trail нельзя просто запустить одновременно на одном мире: они меняют стоимость, сооружения, высоты, оси и другие общие данные. Даже при отсутствии гонок исчезнет согласованное использование общей сети.

Предлагаемый протокол:

- Планировщик резервирует общие стволы, переправы и узлы. Составляет граф конфликтов зон работ с учётом обочин, выемок, подходов и контекста профиля.
- Рабочие задачи читают один снимок и возвращают предложения: линия, профиль, сооружения, изменение поверхности, стоимость, версии прочитанных областей, зона влияния.
- Независимые задачи выполняются одной волной. Пересекающиеся дороги согласуются через общий узел или идут разными волнами. Общий ствол имеет одну задачу.
- Координатор принимает результаты в стабильном порядке идентификаторов, проверяет версии и конфликты, публикует пакет. Время завершения потока не определяет победителя.
- Изменившиеся стоимости не всегда делают соседнее предложение физически неверным, но могут делать его невыгодным. Проверку безопасности и необходимости повторной оптимизации различать.

У каждого работника — свой finder, куча, mutable-кэш и бюджет. Не вызывать общий FastGrid параллельно. Не создавать новый LongRunning поток на каждый сегмент; нужен ограниченный пул и контроль общего количества задач, включая существующий prefetch и параллельное запекание.

RoadRefinement уже распараллеливает уникальные вершины, а Parallel.bands уже предоставляет пул Godot. Использовать существующий опыт, учитывая стоимость копий и счётчиков ссылок GDScript. Для новых локальных задач копировать область влияния, а не весь мир на каждый поток. Мелкие задачи объединять.

Цель — меньше задержка при контролируемых суммарном CPU и памяти. Если ускорение получается за счёт многократного расчёта отвергнутых альтернатив, это отдельный компромисс, а не устранение лишней работы.

## 3. Где запреты мешают и как учитывать земляные работы

### Основное противоречие

Pathfinder._measure_corridor/find_path и StageTrails._road_segment оценивают исходный либо ещё не окончательно сформированный рельеф. ROAD_GRADE=0.22, ROAD_LIMIT=0.28 и BENCH_CROSS=0.65 отсекают шаги. Позже RoadBed и RoadRefinement умеют менять землю: обычное выравнивание, полка дороги до BENCH_LIMIT=4.5 м и тропы до 2 м. Это предельные значения, не обещание фактического изменения на каждом участке.

Грубый пример несоответствия: при полуширине дороги 1.8 м поперечный уклон 0.65 означает около 1.17 м перепада от оси до края. Подготовка полки теоретически может исправить часть таких мест. Но допустимость зависит от обочин, воды, продольного профиля и защитных зон. Нельзя из этого вывести универсальное разрешение всех склонов.

Нужно отличать уклон природной земли, уклон проектного полотна и стоимость формирования этого полотна.

### Перечень ограничений

| Место | Что изменить в будущей реализации |
|---|---|
| Жёсткое отсечение по природному продольному/поперечному уклону | Дешёвая оценка выполнимого профиля и стоимости земляных работ; жёсткие пределы применять к готовому полотну и максимальным объёмам/высотам работ. Не просто увеличить ROAD_LIMIT. |
| RegionRoads отвергает любой результат с туннелем после поиска | Передавать разрешённые сооружения до поиска. Пока регионы не умеют сохранять и воспроизводить туннели, исключать их как варианты заранее. Затем отдельной задачей расширить весь жизненный цикл, а не убрать один if. |
| _protect_structures: вода в радиусе CROSS_GAP=8 получает INF | Разделить физическую защиту сооружения и предпочтение переиспользования. Запрет нового близкого моста заменить ценой и проверкой пользы там, где это безопасно. Существующий настил и его примыкания защищать точно. |
| _fit_safe выключает работы у всех центров поселений в радиусе 10 м, развилок и соседних петель | Для новых поселений сначала проектировать площадь/узел улиц, затем дома. Развилку выравнивать одной задачей. У готовых домов сохранять фундамент. Соседние петли на разных высотах не соединять автоматически. |
| RoadBed/RoadRefinement ослабляют работы у воды и сооружений | Проектировать подход к мосту совместно с мостом; использовать точные уровни воды и закреплённые точки сопряжения вместо универсального запрета на весь берег. Сохранять русло и пропуск воды. |
| _old_places превращает деревья и камни старого плана в непроходимые пятна | В новой области учитывать удаляемую растительность как стоимость расчистки. В закреплённом мире разрешать только после реализации сохранения удаления объектов, обновления чанков и коллизий. Камни разделить на удаляемые объекты и часть рельефа. |
| _detour: предел высоты, только сухая земля, прямоугольное окно, отсечение по числу клеток | Поиск по коридорам с несколькими вариантами высот/работ; оценка физической длины вместо числа шагов. Оставить бюджет и явный ограниченный статус отказа. Снять все ограничения сразу — значит увеличить перебор. |
| state.detour чередует туннель и обход | Выбирать по стоимости, длине, профилю и разнообразию маршрутов. Разнообразие задавать стабильным небольшим предпочтением конкретного прохода, а не порядком обработки предыдущих дорог. |
| Жёсткие лимиты соседей/повторов | Сохранять как защиту времени, но расширять по информативности причины отказа и доступному бюджету. Не принимать исчерпание лимита за доказательство недостижимости. |

Оставить реальные ограничения: вода без допустимого перехода, неосуществимый уклон готового полотна, недостаточный габарит сооружения, пересечение разных высот без соединения, повреждение закреплённых объектов и географии. Замена запрета штрафом расширяет поиск; ожидаемый выигрыш появляется только вместе с хорошей моделью стоимости, коридорами и меньшим числом повторных попыток.

### Общая модель земляных работ

Сделать единый контракт для поиска и построения: ширина/обочина, конечный уклон, допустимые срез и подсыпка, объём работ, уровень воды, укрепление откоса, совместимость с соседней дорогой. Для грубой стадии достаточно дешёвой оценки; точный расчёт только для выбранных участков.

Концептуальная цена: длина + набор высоты + кривизна + объёмы выемки/подсыпки + сооружения + расчистка + воздействие на существующие объекты. Коэффициенты приводить к сопоставимым единицам и задавать отдельно для дороги и тропы. Ограничения безопасности не заменять ценой.

Вначале допустить только сухие локальные работы с ограниченным следом. Перестройка русла и гидрологии — отдельная дорогая операция, которую нельзя неявно разрешить общей подсыпкой. Хранить готовый проект профиля/работ, чтобы загрузчик не пытался восстановить его другой эвристикой. Визуальный меш, движение и коллизии должны читать один результат.

### Проверки будущей реализации

Изолированные синтетические случаи: две долины и один перевал; река с двумя потенциальными переправами; резкий бугор, исправимый малой выемкой; длинный неисправимый подъём; подход к старой сети за препятствием; мост с подходами; общий ствол двух дорог; узел у поселения; серпантин с близкими разноуровневыми петлями; маршрут через границу региона; конфликт двух предложений; отмена и исчерпание бюджета.

Сравнивать последовательный алгоритм с той же архитектурой и параллельный, чтобы не приписать потокам эффект иерархии. Для небольших синтетических карт сравнить качество с полным поиском с допустимой эвристикой. Измерять длину, стоимость, связность, максимальный уклон готового полотна, кривизну/скачки на стыках, объёмы работ, число переправ, раскрытия, CPU, время, память и долю перепланированных участков. Лимиты качества заранее зафиксировать по классам дороги; не объявлять уменьшение числа дорог ускорением без учёта утраченной связности.

Не обещать ускорение в конкретное число раз и не искать оптимальные параметры многократной генерацией мира. Следовать CLAUDE.md/CONTROL.md: изолированные стенды, сторожевые и внешние таймауты, отсутствие повторов после зависания, один интеграционный запуск только при недостаточном покрытии. На этапе этого исследования никакие запуски не нужны.
