# 15.3+ — единое численное ядро воды и проверка паритета

## Решение

Замечание актуально как риск сопровождения: формулы Heightfield и FastGrid
до патча совпадали, LAKE_DROP уже передавался из GDScript в SetWater.
Независимые копии барицентрической интерполяции и литералы допусков всё же
могли разойтись при дальнейших правках. Подтверждённого изменения глубин
этот патч не исправляет; значения констант и порядок арифметики сохранены.

Единственный редактируемый исходник численной математики —
`scripts/core/water_math.gd`. Он содержит:

- барицентрическую высоту треугольника воды;
- интерполяцию двух треугольников базовой сетки земли;
- уровень озера с LAKE_DROP;
- итоговую глубину относительно верхней поверхности реки, озера и моря;
- LAKE_DROP = 0,1 м, TRIANGLE_AREA_EPS = 1e-8, SHORE_EPS = 1e-5,
  LEVEL_EPS = 0,001 м и GRID_EDGE_INSET = 1,001 клетки.

`tools/generate_water_math.py` переводит ограниченный скалярный поднабор
этого исходника в `scripts/core/WaterMath.cs`. C#-файл хранится в репозитории;
обычная сборка и игра не требуют Python. Менять его вручную не следует.
При изменении исходника:

```powershell
python tools/generate_water_math.py
python tools/generate_water_math.py --check
dotnet build --no-restore
& ../Godot_v4.7.2-stable_mono_win64/Godot_v4.7.2-stable_mono_win64_console.exe --headless --path . --script tools/water_parity_test.gd
```

Heightfield использует GDScript-ядро, FastGrid — сгенерированное нативное.
Горячие циклы дорожного генератора остаются целиком на C#: вызовов GDScript
для каждой точки из C# нет. Промежуточные значения — double/float64,
входные packed-массивы и вершины рек по-прежнему float32. WaterBuilder
использует общий уровень озера; его LAKE_DROP оставлен совместимым алиасом.
Heightfield больше не зависит от WaterBuilder ради водных констант.
Отдельный lakeDrop из SetWater удалён: нативное ядро теперь использует ту же
сгенерированную константу, без возможности передать несовместимое значение.

Обход индексов рек и четырёх соседних клеток озера остаётся специфичным для
хранилища каждого языка. Клеточные верхние оценки water_level для генератора
не заменяются точечной глубиной: они намеренно имеют другой смысл.
Мосты, уточнённое дорожное полотно и OuterLand также не добавлены в базовый
C#-сэмплер. fast_water по-прежнему отказывается работать с RoadRefinement
или OuterLand; depth_at сохраняет свои игровые надстройки.

## Проверка паритета

`tools/water_parity_test.gd` не пропускает проверку при отсутствии C#:
нужна актуальная сборка. Перед вычислениями он сверяет SHA-256 канонического
исходника с хешем, встроенным в сгенерированное и собранное C#-ядро.
Переводы строк LF/CRLF нормализуются. Это обнаруживает забытые генерацию
C# или пересборку DLL, включая изменение только констант.

В мире «Север-1234» с базовым планом 256 × 256 проверяются 1000 равномерно
случайных координат. RNG имеет фиксированный seed = 153001; координаты
хранятся как скаляры float64, без промежуточного округления через Vector2.
Heightfield.depth_at и публичный диагностический FastGrid.Depth обходят
свои индексы независимо. Сравниваются сериализованные байты результатов;
допускается также ошибка не более 1e-9 + 1e-10 * max(abs(a), abs(b)) м.
NaN всегда считается ошибкой, бесконечности сравниваются со знаком.

Дополнительно проверяются случайные точки внутри речных треугольников,
вершины берегов и смещения на 1e-7 м, границы карты и точки вне неё,
озёрные границы, выбор максимального уровня из четырёх углов,
смещение озера на 0,1 м, вырожденные треугольники, обратный порядок вершин
и граница барицентрического допуска. В выбранном мире нет озёрных клеток,
поэтому озёрная ветка покрывается отдельным явным синтетическим озером.
Проверяется обновление нативного снимка после изменения высот земли.

Также сравниваются DeepFords при порогах 0,3 и 1,3 м и RoadSegment с
соответствующими проверками GDScript, чтобы покрыть потребителей глубины
в дорожном генераторе.

Результат Godot 4.7.2 / .NET 8:

- 1000/1000 случайных точек мира совпали побайтово;
- всего 3866/3866 точек глубины совпали побайтово;
- среди них 1319 мокрых и 2547 сухих; максимальная ошибка — 0 м;
- все проверки паритета и потребителей глубины прошли.

Успешно выполнены `dotnet build --no-restore` (без ошибок и предупреждений),
`generate_water_math.py --check`, `git diff --check`, а также:

- water_chunk_test;
- water_surface_test;
- water_junction_test;
- bike_water_test;
- water_interaction_test;
- road_safety_test с --route-only;
- river_geometry_test с --synthetic-only --gdscript (без C#-ускорений).

Полная генерация большого мира и FPS не измерялись. Патч меняет организацию
численного кода, сохраняя формулы и границы применимости сэмплеров.
