# Растительность: облегчение дальних деревьев (05.11.2026)

Замер: `tools/forest_scene_perf.gd -- --eye 45` (изолированный смешанный лес, 57,6 тыс. деревьев на 1 км, 1280x720, GTX 1650 SUPER, свет с тенями до 100 м, камера стоит).
Что было видно: тени ≈ 4 из 9,8 мс GPU; уровни LOD0 / LOD1 / LOD2 — по трети остальной нагрузки; у LOD2 ~1400 draw calls. Дорого не число треугольников, а наложение мелких вырезных карточек кроны у дальних деревьев и число узлов (чанк × силуэт × ствол/крона × уровень).

Сделано (каталог `resources/catalog/standard.res` пересобран `tools/bake_assets.gd`, `asset_catalog_test` — пиксели всех LOD совпали):
- LOD1: крона — объединённые ближайшие побеги (было ~25 карточек у сосны, стало ~12), ствол: 4 грани, без ветвей тоньше 0,08 м; LOD2: крона — вдвое реже ещё раз, ствол 3 грани, сечения вдвое реже, только ствол и толстые корни.
- LOD2 у дуба, берёзы, сосны и снежной сосны без отдельного узла ствола (за 160 м он тоньше пикселя и закрыт кроной): -вдвое узлов дальнего уровня. Виды без кроны (сухостой) и остальные ствол сохраняют.

Результат (там же): GPU 10,4 -> 7,6 мс, draw calls 3092 -> 2180, CPU рендера 4,4 -> 2,9 мс, примитивы 9,9 -> 5,7 млн; снимок с воздуха визуально неотличим.

Пробовали и отвергли (не вошло в код):
- группировка LOD1/LOD2 по нескольким чанкам в один MultiMesh: draw calls 2760 -> 1418 и CPU рендера 4,3 -> 1,7 мс, но GPU +1,6 мс (теряется отсечение по чанкам, лишние экземпляры гоняются через вершинный шейдер), на этой видеокарте FPS ниже. Имеет смысл только там, где упор в CPU;
- точное включение уровней по расстоянию до прямоугольника чанка вместо visibility_range: draw calls не уменьшило, а перебор узлов в GDScript съел 30 мс.

Не сделано: тени растительности (согласовать с работой над тенями; LOD1 отбрасывает тени ≈ 1 мс GPU при дальности 100 м), LOD ближнего уровня 0 (стволы 300+ треугольников), трава и подлесок (лёгкие: пучок травы 5 треугольников, формы подлеска до 290).
Известно: `tools/vegetation_test.gd` строка 80 (бюджет 1 мкс) падала и до этой правки.
