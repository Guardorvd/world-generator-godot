# Растительность: облегчение дальних деревьев (05.11.2026)

Замер: `tools/forest_scene_perf.gd -- --eye 45` (изолированный смешанный лес, 57,6 тыс. деревьев на 1 км, 1280x720, GTX 1650 SUPER, свет с тенями до 100 м, камера стоит).
Что было видно: тени ≈ 4 из 9,8 мс GPU; уровни LOD0 / LOD1 / LOD2 — по трети остальной нагрузки; у LOD2 ~1400 draw calls. Дорого не число треугольников, а наложение мелких вырезных карточек кроны у дальних деревьев и число узлов (чанк × силуэт × ствол/крона × уровень).

Сделано (каталог `resources/catalog/standard.res` пересобран `tools/bake_assets.gd`, `asset_catalog_test` — пиксели всех LOD совпали):
- LOD1: крона — объединённые ближайшие побеги (было ~25 карточек у сосны, стало ~12), ствол: 4 грани, без ветвей тоньше 0,08 м; LOD2: крона — вдвое реже ещё раз, ствол 3 грани, сечения вдвое реже, только ствол и толстые корни.
- LOD2 у дуба, берёзы, сосны и снежной сосны без отдельного узла ствола (за 160 м он тоньше пикселя и закрыт кроной): -вдвое узлов дальнего уровня. Виды без кроны (сухостой) и остальные ствол сохраняют.

Результат (там же): GPU 10,4 -> 7,6 мс, draw calls 3092 -> 2180, CPU рендера 4,4 -> 2,9 мс, примитивы 9,9 -> 5,7 млн; снимок с воздуха визуально неотличим.

Пробовали и отвергли (не вошло в код):
- группировка LOD1/LOD2 по нескольким чанкам в один MultiMesh: draw calls 2760 -> 1418 и CPU рендера 4,3 -> 1,7 мс, но GPU +1,6 мс (теряется отсечение по чанкам, лишние экземпляры гоняются через вершинный шейдер), на этой видеокарте FPS ниже. Имеет смысл только там, где упор в CPU;
- точное включение уровней по расстоянию до прямоугольника чанка вместо visibility_range: draw calls не уменьшило, а перебор узлов в GDScript съел 30 мс.

Не сделано: тени растительности (согласовать с работой над тенями; LOD1 отбрасывает тени ≈ 1 мс GPU при дальности 100 м), LOD ближнего уровня 0 (стволы 300+ треугольников), трава и подлесок (лёгкие: пучок травы 5 треугольников, формы подлеска до 290).
Известно: `tools/vegetation_test.gd` строка 80 (бюджет 1 мкс) падала и до этой правки.

## Трава и подлесок (тот же день, второй заход)
Замер `forest_scene_perf -- --eye 28` (лес на 1 км, подлесок и трава включены): вся мелочь вместе стоила 1,5 из 7,1 мс GPU. Самое дорогое: папоротник (96 треугольников, 4128 штук в радиусе травы) и мох (64, 2369 штук) - 0,7 мс, корни (240 x 970) и камни подстилки (1274 x 154) - 0,2 мс; трава (5 треугольников) и остальные формы лёгкие.
Сделано: у папоротника, мха, корней и камней подстилки есть упрощённая форма (48 / 32 / 80 / 180 треугольников, `build_far_meshes` в `understory_models.gd` и `forest_floor.gd`, хранится в каталоге как `far_forms`, каталог VERSION 2). `VegetationLayer._put_understory` кладёт растение дальше `FAR_FORM_R` (24 м) от центра раскладки в группу упрощённой формы; посадка, проверки, поредение и плавное появление те же (обычная отдельная группа снимка).
Результат: GPU 7,1 -> 6,5 мс, примитивы 5,35 -> 4,77 млн, кадров/с 132 -> 142; +4 draw calls.
Не сделано: уровни у крупных форм (куст, подрост, молодые деревья, 100-290 треугольников; их мало), густота ближе 52 м не менялась.

## Draw calls (третий заход)
Состав (eye 45, до правки): ~2180 вызовов, из них около 40% - теневые проходы, остальное - узлы деревьев по чанку x силуэту (4) x части (ствол/крона) x уровню; дальний уровень самый многочисленный. Мелочь - около 30 групп на кадр, сама по себе дёшево.
Группировка по нескольким чанкам (пробовали, отвергнуто) ломает отсечение по чанкам и дороже по GPU. Поэтому:
- на самом дальнем уровне (LOD2) все силуэты вида одного чанка рисуются одним узлом с мешом первого силуэта (высота выровнена по оси Y; цвет и поворот у каждого экземпляра свои): `VegetationLayer._merge_far_variants`, запись `FAR_KEY` в `veg`; отсечение по чанкам прежнее. Ближние уровни не менялись;
- стволы LOD1 не отбрасывают тень (тонкие, дальше 60 м).
Результат (`forest_scene_perf -- --eye 45`): draw calls 2180 -> 1369, CPU рендера 2,9 -> 1,8 мс, GPU 7,6 -> 6,8 мс, p99 кадра в движении 8,7 мс. `vegetation_stream_test`: 0 ошибок.
Всего с начала работы (то же место): draw calls 3092 -> 1369 (-56%), GPU 10,4 -> 6,8 мс.
