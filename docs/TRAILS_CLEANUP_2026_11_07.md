# Пути, тропы, парки: чистка 07.11.2026

Цель — одна понятная схема и меньше лишней работы, без изменения мира там, где он не должен меняться.

## Схема после чистки
- **Дороги и тропы** — `StageTrails` (поселения, вторые пути, тропы к берегам, горные тропы).
- **Природные велосипедные маршруты** — `RideRoutes` в конце `StageTrails`, тем же поиском и той же публикацией ([RIDE_ROUTES.md](RIDE_ROUTES.md)).
- **Велопарки** — `StageTrailPlan` → `TrailWorldNetwork.build(mode = parks)` → `BikePark` ([BIKE_PARKS.md](BIKE_PARKS.md)).
- **Соседние области** — только вид (рельеф, вода, дороги, декор); своих трасс нет.
- **Trail Lab** — отдельно: Scout → Picker → Router → Access → Flow, составитель, запекание.

## Сделано
| Что | Почему | Результат |
|---|---|---|
| Сглаживание линии пути (`_road_line`) одним вызовом C# (`FastGrid.RoadLine`) | раньше вызов C# на каждую точку из GDScript — треть публикации путей | стенд Север-1234: мир путей тот же, `road_line` 1,14 → 0,35 с, этап путей 5,9 → 4,8 с |
| Подготовка `RideRoutes` без обращения к свойству мира в цикле по карте | лишние вызовы на каждую клетку | 2,1 → 1,2 с |
| Соседние области без своей трассы | третий, самый тяжёлый способ делать трассы (до 8 с на область), не совпадал со схемой «парки + природные маршруты» | `region_travel_test` 166 → 137 с; удалены `region_trails.gd`, `prepare_trails`, `from_scout`, два теста |

## Найдено и оставлено (решение за пользователем)
- **Прежняя универсальная сеть** (`--trail-network`: поиск коридоров, маршруты, варианты, районы) — оставлена как откат на время проверки природных маршрутов. После проверки её можно удалить вместе с `TrailSiteSearch`, `TrailCoarseMap`, `TrailPotential`.
- **Соседние области** по-прежнему готовят поселения, дороги и задания. Если они только вид — это следующий кандидат на упрощение.
- **Защита сооружений после каждой тропы** (`_protect_structures` в `_add_trail`, ~0,24 с) — по коду нужна только после нового моста или туннеля, но условие добавит состояние; оставлено.
- **Этап парков** ~15 с в игре: основная часть — общая поверхность (`finish_paths` всей карты, её всё равно ждёт загрузчик) и полная подготовка линий парка (вёрстка, формирование, приёмка). Это механизмы, которые решено сохранить.
- `StageTrailPlan.apply` для одиночного комплекта (без `routes`) в игре больше не встречается, но им пользуются Trail Lab и тесты.
- `region_travel_test`: проверка «узлы ближних областей снова показаны» падает и на прежнем коде (показ строится отдельной задачей после возвращения).
