# Связность поселений и стоимость Trail Network — 04.11.2026

Этот отчёт описывает состояние коммита `ed2efdd` и прежнюю политику 9.8. Последующее
исправление вводит более строгий контракт: все итоговые поселения доступны от старта,
а безопасные дороги отдельных групп сохраняются. См. [уточнение связности и мостового аудита](SETTLEMENT_WATER_BRIDGE_FIX_2026_11_04.md).

## Диагноз связности

Раздельные безопасные сети поселений — предусмотренное изменение 9.8, коммит `9fe9cda`,
а не регрессия интеграции `31154e0`. Это явно описано в `docs/PATCH_9_8.md`:
поселение сохраняется, если связано хотя бы с соседом; соединение разных сетей
дополнительной тропой пробуется, но не гарантируется ценой небезопасного моста.
`46284fe` заменил рост сетей каркасом Краскала, сохранив эту политику.

Старый стенд с двумя безопасными берегами требовал удалить четыре из восьми
поселений. Он проверял прежнюю политику заселения. Дополнительная ошибка стенда:
лямбда принимала `Dictionary`, хотя запись уже имеет тип `SettlementData`.
Рабочий `StageTrails` в окончательном изменении не меняется.

Теперь отдельно проверяются:

- глобальная связность как диагностическое свойство, а не обязательный инвариант;
- существование и взаимность каждой объявленной связи;
- физический путь по маске между концами объявленной связи;
- отсутствие одиночных неподтверждённых поселений, кроме разрешённого первого;
- выбор непустых дальних целей внутри каждой сети и отказ для выдуманной взаимной связи через пролив.

Игровое следствие реального разделения: путь между сетями может отсутствовать,
а навигация возвращает «Проход к цели не найден». Доска доставки берёт соседей
из `world.routes`, дальняя цель проходит граф в `far_destination`: они не обещают
дорожную связь между несоединёнными сетями. Посещения и фотозадания отдельно
выбирают места по расстоянию; отсутствие дороги к ним само по себе не ошибка
связности поселений. Проверка здесь не доказывает достижимость всех таких мест.

## Подтверждённые дефекты Trail Network

1. Состав канонического мира зависел от часов. Поиск получал треть 30-секундного
   бюджета, цикл кандидатов — остаток; запекание могло отказаться посередине по
   тому же дедлайну. Результат сохранялся в кэше навсегда, без продолжения поиска.
   Другой CPU или параллельная нагрузка меняли принятые маршруты при том же сиде.
2. Аудит сравнивал сохранённую вершину с повторной выборкой поверхности. У границы
   вырезки выборка могла обратиться к соседнему или базовому треугольнику.
   Даже неизменённый патч ошибочно считался новой выемкой/насыпью. Изолированный
   `trail_source_audit_test` воспроизводит старый отказ и проверяет исправление.
3. Каждый локальный проект повторно индексировал все дороги захваченного контекста,
   вычислял их профили и копировал словари неизменённых патчей. Входное окно сначала
   копировало полный массив мира, затем уменьшало его. Это не улучшало качество.

## Изменения

- Каноническая сеть использует прежнее ограничение обзора `max(64, N / 1024)` проб
  и завершает каждое предложение один раз. Секундомер служит только диагностике.
  Ограничения геометрического поиска и проверки качества сохранены; квоты трасс нет.
- Высоты центров клеток берутся из готовой сетки/патчей. Зажатые крайние строки
  и столбцы сохраняют прежнее сэмплирование; внешняя потоковая география использует
  общий путь. Окна копируют только свои строки.
- Старые патчи разделяются для чтения, изменяемые словари заменяются при записи.
  Аудит сравнивает существующие вершины непосредственно с сохранённым источником;
  для новых патчей остаётся выборка исходной земли.
- Ограничение земляных работ/защита проверяются уже на округлённой окончательной
  вершине частного запекания. Невозможный кандидат прекращается раньше, без публикации.
  Окончательный аудит всей поверхности остаётся обязательным.
- Локальная метровая сетка индексирует соседние дороги только в нужных клетках,
  включая соседние клетки для общих краёв. Порядок сегментов и разрешение равенств
  сохраняются. Профили старых дорог вне области влияния не рассчитываются.
- Прогресс показывает обработку трасс. `input_ms`, `phases_ms`, `base_surface_ms`
  отделяют обзор, копирование, построение, проверки и подготовку общих дорог.
- План версии 9, слой путей версии 11. Географическая схема не меняется.
  Принятая поверхность передаётся загрузчику; тёплая загрузка и восстановление
  определений не повторяют поиск.

## Измерения и пределы вывода

На этой машине, «Север-1234», план 768, рабочая область трасс 512:

| До исправления часов | Время / объём |
|---|---:|
| Полная генерация | 62,512 с |
| Этап Trail Network вместе с подготовкой поверхности | 39,185 с |
| Сам Network.build с пределом 30 с | 30,115 с |
| Попробовано / предложено / принято | 31 / 78 / 12 |

Подготовка общей поверхности не входила во внутренние 30 с. Последняя попытка
отказалась по времени, а 47 предложений вообще не были обработаны.
Это не означает, что вся разница времени является бесполезной работой.

На сохранённой географии с окончательной политикой поселений старый Network.build
без отсечения рассмотрел 144 предложения, принял 25 и потратил 215,133 с.
Совмещённое сравнение старого и промежуточного нового вариантов остановлено
сторожевым таймером на 300 с; оно **не является успешным сравнением**.
Его не перезапускали и лимит не повышали. Последующие изменения локального индекса
проверены на изолированном стенде; итоговое ускорение полного мира не измерено.
Новый стенд стоимости разделяет эталон и оптимизированный вариант на разные процессы,
по одной сборке за запуск; этот обновлённый полный стенд не запускался.

Точное сравнение локальной подготовки на одной синтетической площадке с существующими дорогами:

| Новый путь | Полная подготовка: полный / локальный индекс | Индексация: полный / локальный |
|---|---:|---:|
| Горная трасса | 208,699 / 182,912 мс | 30,027 / 10,409 мс |
| Тропа | 241,661 / 217,155 мс | 33,466 / 11,944 мс |
| Дорога | 240,830 / 216,414 мс | 31,650 / 10,240 мс |

Все высоты, патчи, общие края, цвета, UV и покрытия совпали; исходная площадка
осталась неизменной. Это ускорение конкретной повторной работы примерно на 10–12%,
а не доказательство такого же выигрыша полного запуска. На маленькой площадке
без старых дорог предварительное определение области индекса само добавляет работу.

В интеграционном прогоне на промежуточной фикстуре с 40 трассами загрузчик подтвердил
холодную передачу поверхности, тёплый кэш, точный повтор определений при потере
производной поверхности, отсутствие деревьев на полотне и начало езды без падения.
Тёплая загрузка этой фикстуры — 2,800 с; восстановление отсутствующей поверхности —
49,333 с. Это разные пути загрузки, не сравнительный замер финального генератора.

Полное детерминированное завершение сети может существенно удлинить холодную генерацию
по сравнению с прежним усечённым результатом. Устранение часов исправляет воспроизводимость,
но не даёт обещания быстрого старта. Основная оставшаяся цена — локальное метровое
формирование каждого кандидата; поиск обзора в измеренных прогонах занимал меньше секунды.
