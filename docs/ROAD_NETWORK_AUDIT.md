# Проверка аудита дорожной сети RN-01…RN-09

Проверка 10 ноября 2026. Метка «подтверждено» из исходного списка не принималась за доказательство. Изменения затрагивают только дорожный поиск, публикацию региональных связей и соответствующие проверки; существующие изменения растительности и велосипедной физики не редактировались.

| Пункт | Вывод и принятое исправление |
| --- | --- |
| RN-01 | Подтверждён воспроизводимым отказом исходной версии. Уже построенные направленные шаги `finder.links` потребляются до подбора нового сооружения. Работает и при присоединении посередине сухого подхода, где оба конца полного моста отсутствуют в новом пути. Клетки существующих осей исключены из запрета переправы. Переноса одного `_same` недостаточно: радиус `REUSE_R = 5` меньше возможного отступа 24 клетки. |
| RN-02 | Подтверждён воспроизводимым отказом исходной версии. Построение сооружений входит в цикл окон; неудача оставляет возможность расширения окна при том же пределе. Запреты переправ обновляют стоимость перед следующим поиском. Текущий предел передаётся мостовому перепоиску, учитывается и при отбрасывании повторной попытки. Общий бюджет сохраняется. |
| RN-03 | Подтверждены раннее удаление одиночных мест и потеря свободного бюджета другого конца. Кандидаты сохраняются до `_retain_connected_settlements`, ориентация меняется при нулевом бюджете цели. `unreachable` не расходует число A* попыток пары компонент. Сама направленная эвристика не заменялась: округление промежуточных проб тоже влияет на её асимметрию, а оптимальность её замены не доказана. |
| RN-04 | Подтверждены единственная цель PLAN, удаление транзитных связей и потеря входящих выходов. PLAN получает до четырёх разнесённых целей без сортировки всего растра. Входящий выход адресует реальное поселение прежней подтверждённой сети либо `plan`. Непубликуемые вершины сворачиваются с сохранением транзитивных связей. Индекс WorldData принимает односторонние записи независимо от порядка ID и удаляет дубликаты рёбер. |
| RN-05 | Подтверждена потеря критериев после перепоиска. Сохраняется штрафная стоимость `_avoiding`; окончательный путь повторно проверяется до принятия сооружений. Неподходящий результат полностью откатывается, включая рекурсивные перепоиски. Это распространено и на ограничение длины берегового ответвления. Для наземных и горных поисков добавлена проверка достижимости; этап вторичных троп останавливается при исчерпании бюджета. |
| RN-06 | Подтверждены разные ограничения двух ветвей объезда и неверная метрика длины. Обе ветви дороги используют ROAD_CLIMB/ROAD_LIMIT; длина считается по физическим шагам с диагоналями. |
| RN-07 | Исправлена подтверждённая рассогласованность выемки туннеля: все изменённые клетки вне прежних осей обновляют высоты поиска; кэш ширины перестраивается при изменении земли и при её откате. Подмостовой проезд остаётся архитектурным ограничением, см. ниже. |
| RN-08 | Подтверждена непроверенная новая дуга при склейке соседних клеток. Склейка теперь возможна только в общей вершине: все оставшиеся рёбра уже проверены A*. Дома расставляются один раз после горных и велосипедных маршрутов. Класс геометрии определяется ограничениями поиска, а не средним уклоном и подписью стиля. RideRoutes проверяет ширину обычной тропы, поскольку она шире предыдущего горного коридора. |
| RN-09 | Подтверждён скрытый дефект сценариев с реками. Нативный расчёт и GDScript используют `max(ground, water_level)` для речных клеток. Сухой берег консервативной маски не опускается до воды. Для обычного стартового плана без рек это не массовый отказ связности. |

## Что намеренно не заменялось

**Два уровня под высоким мостом.** В одной клетке Pathfinder хранит одну высоту и один набор связей. Оставить высоту земли вместо настила — значит лишить настил своего уровня; исключить ось из проекции — значит испортить верхнюю дорогу. Локальная замена из аудита не является корректным исправлением. Полноценный проезд сверху и снизу требует отдельных узлов/слоёв и сохранения выбранного слоя в найденном пути. В этом изменении такая архитектура не вводилась, ограничение RN-07 остаётся.

**Более крупные изменения производительности.** Аллокации `_corridor`, `_avoiding`, `_network_cost`, `_detour`, дополнительные снимки RegionRoads и фоновый prefetch действительно присутствуют. Но наличие прохода по карте само по себе не доказывает, что предложенный журнал изменений, инкрементальный граф или другая политика дадут лучший итог. Без сравнительного профиля они не переписывались. Проверка `can_reach` тоже не бесплатна: она ограничивает бессмысленный A*, но не превращает все случаи в поиск постоянной сложности.

**H_COST = 0.6.** Эвристика недопустима при минимальной цене 0.3; это реальный, уже описанный в коде компромисс. В коде сохранён прежний сравнительный замер. Утверждение про фактическое удвоение длины в текущих мирах данным аудитом не воспроизведено. Глобальное изменение маршрутов и времени поиска на основании одной теоретической оценки не внесено.

**Три ближайших подхода к вершине.** Доказательства, что конкретный отказ исправляется сменой точки подхода, здесь нет; произвольный перебор не добавлен. Проверка недостижимости добавлена независимо от этого.

**Габарит удаления домов.** Размер ±0.55 в `_clear_huts` действительно не описывает любой повёрнутый дом. Но расстановка уже использует реальные `PlayerState.SITE_HALF`, поворот и запас 0.4 м в `_fits`. После переноса расстановки на готовую сеть отдельного доказанного случая касания углом этим аудитом не получено. Произвольно увеличивать удаление домов и снижать вместимость не стали.

## Проверки

- `dotnet build --no-restore`: 0 ошибок, 0 предупреждений.
- `tools/road_network_regression_test.gd`: 0 отказов; ключевые сценарии проходят с GDScript и C#, проверены также лимит мостового перепоиска, диагональная длина, обновление выемок и откат после окончательного отказа.
- Три интеграционных сценария RN-01/02/03 дополнительно запускались с исходным StageTrails из HEAD: все три воспроизводят отказ; новая версия проходит те же сценарии. Контрольные копии находятся только в игнорируемой `.godot`.
- `tools/settlement_network_test.gd`: проверки проходят.
- `tools/route_test.gd`: полный прогон — 0 отказов, включая миры; после последних правок повторён `--quick`, также 0 отказов.
- `tools/region_preparation_test.gd`: 0 отказов.
- `tools/region_rivers_test.gd -- --neighbors`: 0 отказов, включая закрепление следующего соседа и продолжение выхода.
- `tools/road_plan_test.gd -- --seed Ущелье --rides`: сеть 7 поселений связна; 5 мостов; максимальный перепад въезда 0.19 м при пределе 0.25 м, въездов над водой 0; приняты 14 велосипедных спусков, проверка водных участков пройдена. Для запуска в песочнице использована временная копия стенда с кэшем внутри `.godot`, алгоритмы стенда не менялись.

В окружении Godot печатает ошибку доступа к системному хранилищу сертификатов. Она не относится к генерации дорог; приведённые результаты относятся к проверкам стендов. Полный route_test также сообщает об объектах/ресурсах при завершении процесса. Это не заявляется исправленным этим изменением.

Изменения намеренно меняют маршруты, выбор сохранённых поселений и расположение домов; равенство прежних хешей генерации не является критерием приёмки. Четыре цели PLAN и существующие бюджеты остаются ограниченным поиском, а не гарантией проверки каждой возможной переправы. Старые сохранённые ссылки `exit:*` не мигрируются: исправление публикации применяется при новой подготовке областей.
